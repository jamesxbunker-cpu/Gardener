# Gardener

A system supervisor: learns what "normal" looks like for a
multi-channel system, flags anomalies, and (later) can act on them.

## Status

Phase B, in progress. B0 (log format), B1 (log writer), B2 (log
reader), and B3 (`gensim`) are done. B4 (replay) and B5 (wire logging
into `gardener`) are next.

## What Gardener is

Gardener sits above a running system and watches it. Systems — a pump
loop, an HVAC unit, a motor controller, anything with sensors and
actuators — produce a stream of values. Some are measurements (temp,
flow, RPM). Some are controller internals (a PID's setpoint and output).
Some are commands to actuators (pump duty, valve position). Gardener
ingests all of it, builds a picture of what "normal" looks like for that
system over time, and flags when the picture stops matching. It does
not try to hold any value at a target; that is the controller's job.
Gardener's job is to notice when something is wrong that the controller
cannot see because the controller only looks at its own loop.

In its current state Gardener is a C library plus a set of small
command-line tools, running on a PC. It ingests packets, keeps
per-channel history in memory, writes and reads binary logs, and can
be driven by a Python simulated source. Detection, control, and the
dashboard are later phases.

The three data structures to know:

- `channel_desc_t` — static description of one signal. Set once at
  startup from `channels.toml`. Contains the id, name, unit, type,
  role, range, and flags that say whether Gardener may write to it
  and whether it selects a regime.

- `sample_t` — one reading of one channel. 24 bytes in memory, packed
  to 18 bytes on the wire. Contains the value (union of f32/i32/u16/
  bool), the timestamp, and per-sample flags (valid, stale, simulated).

- `packet_t` — one tick's worth of samples from one source. Up to 64
  channels. Two encodings: JSONL for the dev feed and simulated
  sources, and a compact binary form (22 + 18×N bytes, CRC-16/MODBUS)
  for logs and eventually the target link.

## What exists right now

### Library

- **Platform layer** (`plat_now_ns`, `plat_wall_ns`, `plat_sleep_ms`,
  `plat_file_*`, `plat_file_seek`, `plat_file_tell`, `plat_log`) — the
  only code that touches the OS.
- **Channel model** (`ch_type_t`, `ch_role_t`, `channel_desc_t`,
  `sample_t`, `sample_as_f32`) — roles distinguish sensor / setpoint /
  ctrl_out / actuator / status / counter.
- **`ring_t`** — fixed-capacity sample ring. No allocation after init.
- **`registry_t`** — loads channel descriptors from a TOML file,
  provides id → descriptor lookup, and synthesizes placeholders for
  unknown ids.
- **`packet_t`** — in-memory packet struct plus two codecs:
  - JSONL (`packet_from_json`, `packet_to_json`) for the dev feed.
  - Binary (`packet_encode`, `packet_decode`, `packet_crc16`) with
    the CRC-16/MODBUS trailer, for logs and the future target link.
- **`ingest_t`** — per-channel sample rings plus a latest-value
  snapshot. Static storage, no heap.
- **`log_writer_t`** — writes binary logs with a preallocated ring,
  sidecar index, periodic header rewrites, periodic fsync.
- **`log_reader_t`** — reads logs, walks records in logical order,
  does time-range queries using the index, reconstructs the registry
  from the header snapshot.

### Executables and tools

- **`gardener`** — reads JSONL packets from stdin, feeds them to
  ingest, prints stats on exit. (Log writing to be wired in B5.)
- **`gardener-dump`** — two modes: print the channel registry, or
  feed a JSONL file and print the resulting snapshot.
- **`gardener-log`** — reads a binary log and prints its records as
  a table or as JSONL. Supports `--from` / `--to` time filtering via
  the index.
- **`gensim`** (Python) — a simulated source. Emits JSONL packets on
  stdout, driven by a scenario file with fault injection. See
  `tools/gensim/README.md`.

## What does not exist yet

- Replay of a binary log through the ingest path (B4).
- Wiring the log writer into `gardener`'s main loop (B5).
- Baseline learning and detectors (Phase C).
- Control / policy engine (Phase E).
- PC / dashboard link (Phase F).

### Simulated source

Requires Python 3.8+. Optional PyYAML.

    py tools/gensim/gensim.py --scenario tools/gensim/scenarios/normal.yaml --duration 10

    py tools/gensim/gensim.py --scenario tools/gensim/scenarios/sensor_drift.yaml \
        --duration 300 --speed 10 > drift.jsonl

Piping `gensim` into `gardener`:

    py tools/gensim/gensim.py --scenario tools/gensim/scenarios/normal.yaml --duration 30 \
        | ./build/gardener --channels configs/channels.toml

**Windows note:** PowerShell's `>` re-encodes stdout as UTF-16LE on
PowerShell 5.x, which `gardener` cannot parse. Redirect through
`cmd.exe` instead:

    cmd /c "py tools\gensim\gensim.py --scenario ... --duration 300 > drift.jsonl"

Or use PowerShell 7 (`pwsh`), whose `>` defaults to UTF-8.

## Wire format

The binary packet format, locked as of A6:

    Packet (little-endian):
    ┌──────────┬─────────┬───────────────┬──────────┬──────────┬──────────┐
    │ u32 magic│ u16 ver │ u16 source_id │ u64 t_ns │ u16 ch_n │ u16 flags│
    │ "GRDN"   │    1    │               │          │          │          │
    └──────────┴─────────┴───────────────┴──────────┴──────────┴──────────┘
      4 bytes    2          2              8          2           2

    Followed by ch_n × packed sample (18 bytes each), then u16 crc16.

    Packed sample (little-endian):
    ┌─────────┬────────┬────────┬────────┬──────┬──────────┬─────────────────┐
    │ u16 id  │ u8 type│ u8 role│ u8 flag│ u8 _ │ u32 value│ u64 timestamp_ns│
    │ 2 bytes │ 1      │ 1      │ 1      │ 1    │ 4        │ 8               │
    └─────────┴────────┴────────┴────────┴──────┴──────────┴─────────────────┘

Total: 22 + 18 × channel_count bytes.

CRC is CRC-16/MODBUS: poly 0x8005 reflected as 0xA001, init 0xFFFF,
refin/refout true, xorout 0x0000. Check value of `"123456789"` is
`0x4B37`. Chosen because Phase F's target link speaks Modbus and one
CRC implementation covers both.

`packet_encode` returns the number of bytes written, or -1 if the
caller's buffer is too small. `packet_decode` returns the number of
bytes consumed, so a caller can walk a buffer of concatenated packets
by repeatedly advancing by the return value.

## Log format

The binary log, locked as of B0:

- Preallocated at a fixed size (default 100 MB, minimum 1 MB).
- Fixed 4096-byte header with magic, version, file size, offsets,
  counters, timestamps, and a CRC.
- A JSONL registry snapshot immediately after the header.
- Followed by variable-size records, each exactly one `packet_encode`
  output. No framing beyond that; the record's own header gives its
  length.
- A sidecar index file (`X.bin` → `X.idx`) with sparse timestamp →
  offset entries every 256 records. The index is advisory; the log
  alone is sufficient.
- Wraps to `data_start` when full, overwriting oldest records.
  `wrap_count` in the header indicates how many wraps have occurred.

## Configuration

`configs/channels.toml` describes every channel Gardener knows about.
One `[[channel]]` block per signal:

    [[channel]]
    id           = 1
    name         = "coolant_temp"
    unit         = "C"
    type         = "f32"
    role         = "sensor"
    min          = 0
    max          = 150

Fields:

- `id` — required, 0..65535. The wire identifier.
- `name` — required, <= 31 chars. For humans and logs.
- `unit` — optional, <= 15 chars.
- `type` — one of `f32`, `i32`, `u16`, `bool`, `enum` (default `f32`).
- `role` — one of `sensor`, `setpoint`, `ctrl_out`, `actuator`, `status`,
  `counter`. Defaults to `unknown` and logs a warning.
- `min`, `max` — optional, sanity range.
- `controllable` — `true`/`false` (default `false`). May Gardener write
  to this channel?
- `is_regime` — `true`/`false` (default `false`). Marks the channel as
  a regime selector for baseline segmentation.

The parser handles a small TOML subset: `[[table]]` headers and
`key = value` lines with quoted strings, numbers, and booleans.
Trailing comments on a value line are *not* stripped — put comments on
their own line. Nested tables and arrays are not supported.

## Design notes

### Data model

- `sample_t` is natural-aligned in memory (24 bytes) and packs to 18
  bytes on the wire. Both sizes are asserted by tests.
- `ROLE_UNKNOWN = 0`. Zero-initialized descriptors mean "unknown", not
  "sensor". Unknown channels get logged and are easy to spot.
- Unknown channel ids are synthesized into the registry on first sight
  and cached. Samples are stored normally; the descriptor has
  `role = ROLE_UNKNOWN` so downstream detectors can see they're
  unclassified.
- Every sample in a ring has exactly one of `CH_FLAG_VALID` or
  `CH_FLAG_STALE` set. Detectors can rely on that.
- Per-sample timestamps win over packet timestamps; zero means
  "inherit".
- `PACKET_FLAG_SIMULATED` propagates to `CH_FLAG_SIMULATED` on every
  sample. Detectors can down-weight simulated input in a mixed
  environment.

### Constants and bounds

- `REGISTRY_MAX_CHANNELS = 256`, arena 64 B/channel. Both compile-time.
- `ingest_t` is static: `REGISTRY_MAX_CHANNELS × INGEST_RING_CAP`
  samples, ~6.3 MB total. No heap, no allocation after init.
- `INGEST_RING_CAP = 1024` samples per channel (~102 s at 10 Hz).
- `PACKET_MAX_CH = 64`. Keeps `packet_t` around 1.5 KB so it can live
  on the stack.
- A packet with more than `PACKET_MAX_CH` channels is rejected before
  any counter is bumped. `packets_seen` counts *accepted* packets, not
  received ones.

### Registry

- Registry string storage lives in a fixed arena inside the registry
  struct. No heap; the registry is trivially copyable and embeddable
  in a larger static struct (as `ingest_t` does).
- Registry loads are append-only. Calling `registry_load_toml` twice
  on the same registry doubles its entries. Add a `registry_clear`
  when runtime reload is needed.
- A `[[channel]]` with no `name` is dropped with a warning. One with
  no `role` is kept with `ROLE_UNKNOWN` and a warning.

### Codecs

- `packet_from_json` honors an explicit `"type"` for both the type tag
  and the union bytes. Inferred types (when `"type"` is absent) pick
  i32 for whole numbers and f32 otherwise.
- `packet_to_json` returns the length the full encoding needs, even if
  the caller's buffer was too small. Callers detect truncation by
  comparing the return value to `cap`.
- `find_key` in `packet.c` stops at the end of the current object.
  This keeps a key like `"type"` in a later entry of the same packet
  from being matched while parsing an earlier entry.
- The binary wire format is little-endian on every field, byte-by-byte
  written and read, so the codec is independent of host endianness
  and alignment.
- `packet_decode` returns bytes consumed, not the buffer length. A
  caller walks a stream of concatenated packets by repeatedly
  advancing past the return value.
- The CRC is CRC-16/MODBUS, not CRC-16/ARC. The names are close and
  easy to confuse; the check value in the test pins which one this is.

### Log

- The log is preallocated at a fixed size and wraps in place. Header,
  registry snapshot, and index are the only metadata.
- `log_writer` refuses to open a file with a bad header unless
  `start_fresh` is set. This prevents silently overwriting a possibly
  valuable file that just happens to be corrupt.
- `log_reader_seek_ns` positions the reader so a following
  `log_reader_next` returns the first record with `ts >= target`.
- `log_reader_prev` is not implemented. Backward iteration would need
  a small ring of recent offsets in the reader. Nothing currently
  needs it.

### Platform

- No OS headers outside `src/platform/`. This keeps the eventual MCU
  port (V2) a folder swap rather than a rewrite.
- `plat_log` writes to `stderr` only. `stdout` is reserved for
  machine-readable output (dump tool, JSONL stream).
