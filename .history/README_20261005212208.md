# Gardener

A system supervisor: learns what "normal" looks like for a
multi-channel system, flags anomalies, and (later) can act on them.

## Status

Phase A3 — ingest engine.

What exists:

- Platform layer (`plat_now_ns`, `plat_wall_ns`, `plat_sleep_ms`,
  `plat_file_*`, `plat_log`) — the only code that touches the OS.
- Channel model: `ch_type_t`, `ch_role_t`, `channel_desc_t`, `sample_t`,
  `sample_as_f32`. Roles distinguish sensor / setpoint / ctrl_out /
  actuator / status / counter so a supervisor can treat a PID loop's
  internals correctly.
- `ring_t` — fixed-capacity sample ring per channel. No allocation after
  init.
- `registry_t` — loads channel descriptors from a TOML file, provides
  id → desc lookup, and synthesizes placeholders for unknown channels.
- `packet_t` — in-memory struct for one tick's worth of samples from one
  source. Wire format arrives in A4 (JSONL) and A6 (binary).
- `ingest_t` — per-channel sample rings plus a latest-value snapshot.
  Takes packets in, exposes history and current values out. Static
  storage, no heap. Embeds the registry so channel metadata is always
  available where samples land.
- `gardener-dump` tool — loads a registry and prints the channel table.
- `gardener` executable with `--version`, `--verbose`, `--quiet`, and a
  short tick loop that exercises the platform timer and signal handling.

What does not exist yet:

- JSONL packet feed (A4).
- `gardener-dump` feed mode (A5).
- Binary packet codec (A6).

Target link and dashboard are later phases.

## Build

    cmake -B build
    cmake --build build

## Run

    ./build/gardener --version
    ./build/gardener --verbose
    ./build/gardener --quiet

    ./build/gardener-dump --config configs/channels.toml

## Test

    cd build && ctest --output-on-failure

Four test suites currently:

- `platform` — time monotonicity, sleep, file round-trip, log level filter.
- `ring` — init, push, wrap, indexed access, capacity-1 edge case, and a
  static assertion that `sample_t` stays 24 bytes in memory.
- `registry` — empty file, missing file, full channel with every field,
  multiple channels, comments and blank lines, unknown keys, unknown
  type and role, missing name dropped, `registry_get_or_default`
  synthesis, capacity limit.
- `ingest` — init with and without a config, NULL safety, single and
  multi-channel feeds, ring accumulation and wrap, unknown-channel
  synthesis and caching, timestamp inheritance and override,
  simulated-flag propagation, stale-flag preservation, out-of-range
  ids dropped, oversized packets rejected, type/role fill-in from the
  descriptor.

## Layout

    include/gardener/   public headers
      platform.h          the OS boundary
      channel.h           channel types, roles, sample_t
      ring.h              fixed-capacity sample ring
      registry.h          channel descriptor registry
      packet.h            in-memory packet struct
      ingest.h            per-channel rings and latest-value snapshot
    src/                implementation
      main.c              entry point
      ring.c              ring buffer
      registry.c          TOML subset loader and lookup
      ingest.c            packet → rings, unknown-channel handling
      platform/           the only place OS APIs are called
      tools/              dev tools (gardener-dump)
    tests/              unit tests
    configs/            channels.toml — one [[channel]] block per signal

## Configuration

`configs/channels.toml` describes every channel Gardener knows about.
One `[[channel]]` block per signal:

    [[channel]]
    id           = 1
    name         = "coolant_temp"
    unit         = "C"
    type         = "f32"
    role         = "sensor"
    min          = 0
    max          = 150

Fields:

- `id` — required, 0..65535. The wire identifier.
- `name` — required, <= 31 chars. For humans and logs.
- `unit` — optional, <= 15 chars.
- `type` — one of `f32`, `i32`, `u16`, `bool`, `enum` (default `f32`).
- `role` — one of `sensor`, `setpoint`, `ctrl_out`, `actuator`, `status`,
  `counter`. Defaults to `unknown` and logs a warning.
- `min`, `max` — optional, sanity range for the range-check detector.
- `controllable` — `true` / `false` (default `false`). May Gardener write
  to this channel?
- `is_regime` — `true` / `false` (default `false`). Marks the channel as
  a regime selector for baseline segmentation.

The parser handles a small TOML subset: `[[table]]` headers and
`key = value` lines with quoted strings, numbers, and booleans.
Trailing comments on a value line are *not* stripped — put comments on
their own line. Nested tables and arrays are not supported.

## Design notes

- `sample_t` is natural-aligned in memory (24 bytes) and will be packed to
  18 bytes on the wire in A6. The 24-byte size is asserted by a test so
  the ingest storage math can't silently change.
- `ROLE_UNKNOWN = 0`. Zero-initialized descriptors mean "unknown", not
  "sensor". Unknown channels get logged and are easy to spot.
- `plat_log` writes to `stderr` only. `stdout` is reserved for
  machine-readable output (dump tool, JSONL stream).
- No OS headers outside `src/platform/`. This keeps the eventual MCU port
  (V2) a folder swap rather than a rewrite.
- Registry string storage lives in a fixed arena inside the registry
  struct. No heap; the registry is trivially copyable and embeddable in
  a larger static struct (as A3's ingest does).
- Registry loads are append-only. Calling `registry_load_toml` twice on
  the same registry doubles its entries. Add a `registry_clear` when
  runtime reload is needed.
- A `[[channel]]` with no `name` is dropped with a warning. One with no
  `role` is kept with `ROLE_UNKNOWN` and a warning.
- `REGISTRY_MAX_CHANNELS` is 256, and the string arena is 64 bytes per
  channel. Both are compile-time constants; bump them if a system needs
  more or longer-named channels.
- `ingest_t` is static: `REGISTRY_MAX_CHANNELS` × `INGEST_RING_CAP`
  samples, ~6.3 MB total with the embedded registry. No heap, no
  allocation after init. Fits on an MCU with external RAM or a modest
  SBC.
- `INGEST_RING_CAP` is 1024 samples per channel — ~102 s of history at
  10 Hz. Enough for the baseline and rate-of-change detectors in Phase
  C; resize when their windows become concrete.
- `PACKET_MAX_CH` is 64, smaller than `REGISTRY_MAX_CHANNELS` on
  purpose. A single tick carries one source's worth of channels, not the
  whole registry. Keeps `packet_t` around 1.5 KB so it can live on the
  stack.
- Unknown channel ids are synthesized into the registry on first sight
  and cached. Samples are stored normally; the descriptor has
  `role = ROLE_UNKNOWN` so downstream detectors can see they're
  unclassified.
- A packet with more than `PACKET_MAX_CH` channels is rejected before
  any counter is bumped. `packets_seen` counts *accepted* packets, not
  received ones.
- Every sample in a ring has exactly one of `CH_FLAG_VALID` or
  `CH_FLAG_STALE` set. Detectors can rely on that.
- Timestamps: a sample's own `timestamp_ns` wins; if zero, the packet's
  timestamp is inherited.
- `PACKET_FLAG_SIMULATED` propagates to `CH_FLAG_SIMULATED` on every
  sample. Detectors can down-weight simulated input in a mixed
  environment.
