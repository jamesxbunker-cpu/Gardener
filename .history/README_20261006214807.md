# Gardener

A system supervisor: learns what "normal" looks like for a
multi-channel system, flags anomalies, and (later) can act on them.

## Status

Phase B, in progress. B0 (log format), B1 (log writer), B2 (log
reader), and B3 (`gensim`) are done. B4 (replay) and B5 (wire logging
into `gardener`) are next.

The library reads packets from stdin (JSONL), stores per-channel
history, writes and reads a binary log with a sidecar index, and has
a simulated source that produces realistic packet streams with
injectable faults. Detection, control, and the dashboard are later
phases.

## What Gardener is

Gardener sits above a running system and watches it. Systems — a pump
loop, an HVAC unit, a motor controller, anything with sensors and
actuators — produce a stream of values. Some are measurements (temp,
flow, RPM). Some are controller internals (a PID's setpoint and output).
Some are commands to actuators (pump duty, valve position). Gardener
ingests all of it, builds a picture of what "normal" looks like for that
system over time, and flags when the picture stops matching. It does
not try to hold any value at a target; that is the controller's job.
Gardener's job is to notice when something is wrong that the controller
cannot see because the controller only looks at its own loop.

In its current state Gardener is a C library plus a set of small
command-line tools, running on a PC. It ingests packets, keeps
per-channel history in memory, writes and reads binary logs, and can
be driven by a Python simulated source. Detection, control, and the
dashboard are later phases.

The three data structures to know:

- `channel_desc_t` — static description of one signal. Set once at
  startup from `channels.toml`. Contains the id, name, unit, type,
  role, range, and flags that say whether Gardener may write to it
  and whether it selects a regime.

- `sample_t` — one reading of one channel. 24 bytes in memory, packed
  to 18 bytes on the wire. Contains the value (union of f32/i32/u16/
  bool), the timestamp, and per-sample flags (valid, stale, simulated).

- `packet_t` — one tick's worth of samples from one source. Up to 64
  channels. Two encodings: JSONL for the dev feed and simulated
  sources, and a compact binary form (22 + 18×N bytes, CRC-16/MODBUS)
  for logs and eventually the target link.

## What exists right now

### Library

- Platform layer (`plat_now_ns`, `plat_wall_ns`, `plat_sleep_ms`,
  `plat_file_*`, `plat_file_seek`, `plat_file_tell`, `plat_log`) — the
  only code that touches the OS.
- Channel model: `ch_type_t`, `ch_role_t`, `channel_desc_t`, `sample_t`,
  `sample_as_f32`. Roles distinguish sensor / setpoint / ctrl_out /
  actuator / status / counter.
- `ring_t` — fixed-capacity sample ring. No allocation after init.
- `registry_t` — loads channel descriptors from a TOML file, provides
  id → descriptor lookup, and synthesizes placeholders for unknown ids.
- `packet_t` — in-memory packet struct plus two codecs:
  - JSONL (`packet_from_json`, `packet_to_json`) for the dev feed.
  - Binary (`packet_encode`, `packet_decode`, `packet_crc16`) with
    the CRC-16/MODBUS trailer, for logs and the future target link.
- `ingest_t` — per-channel sample rings plus a latest-value snapshot.
  Static storage, no heap.
- `log_writer_t` — writes binary logs with a preallocated ring,
  sidecar index, periodic header rewrites, periodic fsync.
- `log_reader_t` — reads logs, walks records in logical order, does
  time-range queries using the index, and reconstructs the registry
  from the header snapshot.

### Executables and tools

- `gardener` — reads JSONL packets from stdin, feeds them to ingest,
  prints stats on exit. (Log writing to be wired in B5.)
- `gardener-dump` — two modes: print the channel registry, or feed
  a JSONL file and print the resulting snapshot.
- `gardener-log` — reads a binary log and prints its records as a
  table or as JSONL. Supports `--from` / `--to` time filtering via
  the index.
- `gensim` (Python) — a simulated source. Emits JSONL packets on
  stdout, driven by a scenario file with fault injection. See
  `tools/gensim/README.md`.

## What does not exist yet

- Replay of a binary log through the ingest path (B4).
- Wiring the log writer into `gardener`'s main loop (B5).
- Baseline learning and detectors (Phase C).
- Control / policy engine (Phase E).
- PC / dashboard link (Phase F).

    py tools/gensim/gensim.py --scenario tools/gensim/scenarios/normal.yaml --duration 10

    py tools/gensim/gensim.py --scenario tools/gensim/scenarios/sensor_drift.yaml \
        --duration 300 --speed 10 > drift.jsonl

Piping `gensim` into `gardener`:

    py tools/gensim/gensim.py --scenario tools/gensim/scenarios/normal.yaml --duration 30 \
        | ./build/gardener --channels configs/channels.toml

**Windows note:** PowerShell's `>` re-encodes stdout as UTF-16LE on
PowerShell 5.x, which `gardener` cannot parse. Redirect through
`cmd.exe` instead:

    cmd /c "py tools\gensim\gensim.py --scenario ... --duration 300 > drift.jsonl"

Or use PowerShell 7 (`pwsh`), whose `>` defaults to UTF-8.

## Wire format

The binary packet format, locked as of A6:

    Packet (little-endian):
    ┌──────────┬─────────┬───────────────┬──────────┬──────────┬──────────┐
    │ u32 magic│ u16 ver │ u16 source_id │ u64 t_ns │ u16 ch_n │ u16 flags│
    │ "GRDN"   │    1    │               │          │          │          │
    └──────────┴─────────┴───────────────┴──────────┴──────────┴──────────┘
      4 bytes    2          2              8          2           2

    Followed by ch_n × packed sample (18 bytes each), then u16 crc16.

    Packed sample (little-endian):
    ┌─────────┬────────┬────────┬────────┬──────┬──────────┬─────────────────┐
    │ u16 id  │ u8 type│ u8 role│ u8 flag│ u8 _ │ u32 value│ u64 timestamp_ns│
    │ 2 bytes │ 1      │ 1      │ 1      │ 1    │ 4        │ 8               │
    └─────────┴────────┴────────┴────────┴──────┴──────────┴─────────────────┘

Total: 22 + 18 × channel_count bytes.

CRC is CRC-16/MODBUS: poly 0x8005 reflected as 0xA001, init 0xFFFF,
refin/refout true, xorout 0x0000. Check value of `"123456789"` is
`0x4B37`.

## Log format

The binary log, locked as of B0:

- Preallocated at a fixed size (default 100 MB, minimum 1 MB).
- Fixed 4096-byte header with magic, version, file size, offsets,
  counters, timestamps, and a CRC.
- A JSONL registry snapshot immediately after the header.
- Followed by variable-size records, each exactly one `packet_encode`
  output. No framing beyond that; the record's own header gives its
  length.
- A sidecar index file (`X.bin` → `X.idx`) with sparse timestamp →
  offset entries every 256 records. The index is advisory; the log
  alone is sufficient.
- Wraps to `data_start` when full, overwriting oldest records.
  `wrap_count` in the header indicates how many wraps have occurred.

## Test

    cd build && ctest --output-on-failure

Nine test suites currently. Each is a standalone executable that locks
in the behavior of one module, so that when the project grows —
detectors, network link, dashboard — a regression in a lower layer
shows up immediately, in a test named after that layer, rather than as
a mysterious wrong number coming out of the top of the stack.

### `test_platform`

Tests the platform layer, which is the only module allowed to call OS
APIs directly. Everything else goes through it.

What it checks and why:

- **Monotonic time moves forward.** `plat_now_ns()` is what all
  timestamps eventually trace back to. The test sleeps 20 ms and
  asserts the clock advanced by 15–10000 ms.
- **Wall clock is plausible.** `plat_wall_ns()` returns something
  after 2020-01-01 in nanoseconds. Fails loudly if the RTC is unset.
- **Sleep returns on time.** `plat_sleep_ms(30)` actually sleeps.
- **File write/read round-trip.** Write a payload, read it back,
  confirm content and EOF.
- **Missing file returns NULL.** Opening a nonexistent path returns
  NULL, not a broken handle.
- **NULL safety.** All file functions handle NULL.
- **Log levels filter.** Setting level to ERROR suppresses DEBUG.

### `test_ring`

Tests the sample ring, which is the storage behind every channel.

What it checks and why:

- **Bad arguments rejected at init.** NULL, cap 0 → -1.
- **Push under capacity preserves order.**
- **Push exactly to capacity.** Boundary condition.
- **Wrap overwrites oldest.** The core invariant.
- **Wrap twice.** Modular arithmetic after multiple laps.
- **Clear.** Reset without reallocation.
- **Capacity 1.** Degenerate case.
- **`sample_as_f32` for every type.** Detector contract.
- **`sample_t` is 24 bytes with fixed field offsets.** Static
  assertion that pins layout and prevents silent storage-math drift.

### `test_registry`

Tests the config loader.

What it checks and why:

- **Empty file loads cleanly.**
- **Missing file is a hard error.**
- **Full channel with every field.**
- **Multiple channels.**
- **Comments and blank lines.** Also documents the trailing-comment
  limitation (not stripped).
- **Unknown key warns and counts.**
- **Unknown type and role.** Falls back to defaults.
- **Missing name drops the channel.**
- **`registry_get_or_default` synthesizes and caches.**
- **`registry_get_or_default` returns existing.**
- **Capacity limit.** Config cannot overrun the fixed array.

### `test_ingest`

Tests the ingest engine, where packets become per-channel history.

What it checks and why:

- **NULL arguments rejected.**
- **Init without config.**
- **Single-channel round-trip.**
- **Three channels in one packet.**
- **Ring accumulates.**
- **Ring wraps.**
- **Unknown channel synthesized.**
- **Unknown channel cached.** Counts feeds, not registrations.
- **Timestamp inheritance and override.**
- **Simulated flag propagates.** Packet flag → sample flag.
- **Stale flag preserved, valid not set.** The VALID/STALE invariant.
- **Out-of-range id dropped.**
- **Oversized packet rejected before counting.**
- **Type/role fill-in from descriptor.**
- **Mixed known and unknown in one packet.**
- **`has_channel` false before any feed.**
- **Accessors respect bounds.**

### `test_packet_json`

Tests the JSONL encoder and decoder.

What it checks and why:

- **Decode one f32.** Canonical shape.
- **Decode multiple channels.** This caught the `find_key` scoping bug
  — a `"type"` in one entry must not leak into another.
- **Explicit type wins.** Caught a type/union mismatch bug.
- **Shorthand `v` map.** Hand-typed input convenience.
- **Whitespace tolerance.**
- **Unknown keys ignored.**
- **Key order irrelevant.**
- **Negative numbers.**
- **Malformed input returns -1.** Empty, missing keys, empty arrays,
  not-JSON.
- **Encode basics and bool.**
- **Round-trip.**
- **NULL and zero-cap.**
- **Returns needed length, not written length.** The truncation
  contract. Caught a bug in the append helper.

### `test_packet_bin`

Tests the binary encoder and decoder.

What it checks and why:

- **Encoded size formula** `22 + 18 × N`.
- **Worst case fits in `PACKET_BIN_MAX`.**
- **Round-trip empty.**
- **Round-trip one f32.**
- **Round-trip all types.** f32, i32, bool, u16, enum.
- **Round-trip all flags.**
- **Encode NULL and cap-too-small.**
- **Encode too many channels.**
- **Decode NULL and too-short buffer.**
- **Bad magic.** Catches random file read as packet.
- **Bad version.** Hard gate.
- **Bad CRC.** Bit rot protection.
- **Channel count exceeds max.** Checked independently of CRC.
- **Buffer shorter than claimed.**
- **Two packets concatenated.** The stream-walking contract.
- **CRC-16/MODBUS check vector.** `packet_crc16("123456789", 9) == 0x4B37`.

### `test_log_format`

Tests the log format's structural constants and layout.

What it checks and why:

- **Constants.** `LOG_MAGIC`, `LOG_VERSION`, `LOG_HEADER_SIZE`, index
  constants.
- **Header size and field offsets.** Locked so reordering requires a
  version bump.
- **Index header and entry sizes and offsets.**
- **Record size formula matches `packet_encode`.** For N channels,
  `log_record_size(N)` must equal what the encoder produces. This is
  the invariant the log writer and reader depend on.
- **Minimum log size holds enough records to be useful.**
- **Registry snapshot fits within the default log's budget.**

### `test_log_writer`

Tests the log writer.

What it checks and why:

- **Open/create/close.** Empty log has a valid header.
- **Append one and read back.** Round-trip of a single packet.
- **Append many and read back.** 100 packets, verify order.
- **Reopen appends.** Second session continues where the first left
  off. This caught two bugs: `last_wall_ns` was being set *after* the
  header CRC was computed, invalidating every header that carried a
  valid CRC.
- **Wrap overwrites oldest.** Fill a small log past capacity, verify
  `wrap_count` rises.
- **Refuse invalid header.** A log with a bad magic must not be
  silently overwritten without `start_fresh`.
- **Min size refused.** Logs below `LOG_MIN_MAX` are rejected.
- **NULL args.**

### `test_log_reader`

Tests the log reader.

What it checks and why:

- **Open missing file returns NULL.**
- **Open NULL arg returns NULL.**
- **Close NULL is safe.**
- **Open empty and iterate.** Zero records, first `next` returns 0.
- **Write/read five.** Timestamps and values round-trip in order.
- **Rewind.** After iterating, `rewind` resets to the beginning.
- **Registry snapshot.** The header's JSONL is reconstructed into a
  usable `registry_t` with correct names, units, roles, types, and
  flags.
- **Seek.** `--from`/`--to` semantics: `seek_ns(250)` lands on 300;
  `seek_ns(500)` lands on 500; `seek_ns(0)` lands on 0;
  `seek_ns(9999)` returns end-of-log.
- **NULL safety.** Every accessor handles NULL.

## Configuration

`configs/channels.toml` describes every channel Gardener knows about.
One `[[channel]]` block per signal:

    [[channel]]
    id           = 1
    name         = "coolant_temp"
    unit         = "C"
    type         = "f32"
    role         = "sensor"
    min          = 0
    max          = 150

Fields:

- `id` — required, 0..65535.
- `name` — required, <= 31 chars.
- `unit` — optional, <= 15 chars.
- `type` — one of `f32`, `i32`, `u16`, `bool`, `enum` (default `f32`).
- `role` — one of `sensor`, `setpoint`, `ctrl_out`, `actuator`, `status`,
  `counter`. Defaults to `unknown` and logs a warning.
- `min`, `max` — optional, sanity range.
- `controllable` — `true`/`false` (default `false`).
- `is_regime` — `true`/`false` (default `false`).

The parser handles a small TOML subset: `[[table]]` headers and
`key = value` lines with quoted strings, numbers, and booleans.
Trailing comments on a value line are *not* stripped. Nested tables
and arrays are not supported.

## Design notes

- `sample_t` is 24 bytes in memory with fixed field offsets; 18 bytes
  packed on the wire. Both sizes are asserted by tests.
- `ROLE_UNKNOWN = 0`. Zero-initialized descriptors mean "unknown", not
  "sensor".
- `plat_log` writes to `stderr` only. `stdout` is reserved for
  machine-readable output.
- No OS headers outside `src/platform/`. Keeps the eventual MCU port
  a folder swap rather than a rewrite.
- Registry string storage lives in a fixed arena. No heap; the registry
  is trivially copyable and embeddable.
- Registry loads are append-only.
- `REGISTRY_MAX_CHANNELS = 256`, arena 64 B/channel.
- `ingest_t` is static: ~6.3 MB. No heap.
- `INGEST_RING_CAP = 1024` per channel (~102 s at 10 Hz).
- `PACKET_MAX_CH = 64`. Keeps `packet_t` on the stack.
- Unknown channel ids are synthesized into the registry on first sight
  and cached.
- Rejected packets don't increment `packets_seen`.
- Every sample in a ring has exactly one of `VALID` or `STALE` set.
- Per-sample timestamps win over packet timestamps.
- `PACKET_FLAG_SIMULATED` propagates to `CH_FLAG_SIMULATED`.
- JSONL: explicit `"type"` wins; inferred types pick i32 for whole
  numbers, f32 otherwise.
- `packet_to_json` returns the needed length; callers detect
  truncation by comparing to `cap`.
- `find_key` in `packet.c` stops at the end of the current object.
- Binary wire format is little-endian on every field, independent of
  host endianness and alignment.
- `packet_decode` returns bytes consumed, so callers can walk a
  stream.
- The CRC is CRC-16/MODBUS, not CRC-16/ARC.
- The log is preallocated at a fixed size and wraps in place. Header,
  registry snapshot, and index are the only metadata.
- `log_writer` refuses to open a file with a bad header unless
  `start_fresh` is set.
- `log_reader_seek_ns` positions the reader so a following
  `log_reader_next` returns the first record with `ts >= target`.
- `log_reader_prev` is not implemented. Backward iteration would need
  a small ring of recent offsets in the reader. Nothing currently
  needs it.
