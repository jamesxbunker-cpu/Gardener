# Gardener

A system supervisor: learns what "normal" looks like for a
multi-channel system, flags anomalies, and (later) can act on them.

## Status

Phase A5 — `gardener-dump` feed mode. Phase A is nearly complete.

## What Gardener is

Gardener sits above a running system and watches it. Systems — a pump
loop, an HVAC unit, a motor controller, anything with sensors and
actuators — produce a stream of values. Some are measurements (temp,
flow, RPM). Some are controller internals (a PID's setpoint and output).
Some are commands to actuators (pump duty, valve position). Gardener
ingests all of it, builds a picture of what "normal" looks like for that
system over time, and flags when the picture stops matching. It does
not try to hold any value at a target; that is the controller's job.
Gardener's job is to notice when something is wrong that the controller
cannot see because the controller only looks at its own loop.

In its current state Gardener is a library plus two small executables
running on a PC. It reads packets of samples from stdin, stores them per
channel in fixed-size rings, and can dump a snapshot of what it knows.
Detection, logging, control, and the dashboard are later phases.

The three data structures to know:

- `channel_desc_t` — static description of one signal. Set once at
  startup from `channels.toml`. Never changes while running. Contains
  the id, name, unit, type, role, range, and flags that say whether
  Gardener may write to it and whether it selects a regime.

- `sample_t` — one reading of one channel. 24 bytes in memory. Contains
  the value (union of f32/i32/u16/bool), the timestamp, and per-sample
  flags (valid, stale, simulated).

- `packet_t` — one tick's worth of samples from one source. Up to 64
  channels. Travels as one JSONL line over stdin.

## What exists right now

- Platform layer (`plat_now_ns`, `plat_wall_ns`, `plat_sleep_ms`,
  `plat_file_*`, `plat_log`) — the only code that touches the OS.
- Channel model: `ch_type_t`, `ch_role_t`, `channel_desc_t`, `sample_t`,
  `sample_as_f32`. Roles distinguish sensor / setpoint / ctrl_out /
  actuator / status / counter so Gardener can treat a PID loop's
  internals correctly.
- `ring_t` — fixed-capacity sample ring. No allocation after init.
- `registry_t` — loads channel descriptors from a TOML file, provides
  id → descriptor lookup, and synthesizes placeholders for unknown ids.
- `packet_t` — in-memory packet struct plus JSONL encode/decode.
- `ingest_t` — per-channel sample rings plus a latest-value snapshot.
  Static storage, no heap. Embeds the registry so channel metadata is
  always available where samples land.
- `gardener` executable — reads JSONL packets from stdin, feeds them
  to ingest, prints stats on exit.
- `gardener-dump` tool — two modes: print the channel registry, or feed
  a JSONL file and print the resulting snapshot.

## What does not exist yet

- Binary packet codec (A6). JSONL works; binary is next.
- Persistent sample logging (Phase B).
- Simulated source and replay (Phase B).
- Baseline learning and detectors (Phase C).
- PC / dashboard link (Phase F and Phase 5 of the later plan).

## Test

    cd build && ctest --output-on-failure

Each test is a standalone executable. They exist to lock in the
behavior of one module at a time, so that when the project grows —
detectors, log writer, network link — a regression in a lower layer
shows up immediately, in a test named after that layer, rather than as
a mysterious wrong number coming out of the top of the stack.

### `test_platform`

Tests the platform layer, which is the only module allowed to call OS
APIs directly. Everything else goes through it, so a bug here looks
like a bug everywhere.

What it checks and why:

- **Monotonic time moves forward.** `plat_now_ns()` is what all
  timestamps eventually trace back to. If it is not strictly
  monotonic, ordering samples and computing rates is undefined. The
  test sleeps 20 ms and asserts the clock advanced by at least 15 ms
  and less than 10 s. The upper bound catches a clock that jumped
  to epoch or similar.
- **Wall clock is plausible.** `plat_wall_ns()` is used in logs where
  we want timestamps comparable across reboots. If the RTC is unset
  (some CI environments, some dev boards), it returns 0 and this test
  fails loudly rather than letting every log line read `1970-01-01`.
- **Sleep returns on time.** `plat_sleep_ms(30)` must actually sleep
  ~30 ms, not return immediately. If it did, all later polling loops
  would busy-spin.
- **File write/read round-trip.** Writes a known payload, reads it
  back, checks the content and that the next read reports EOF. Any
  `plat_file_*` bug propagates into the log writer in Phase B.
- **Missing file returns NULL.** Opening a nonexistent path must
  return NULL, not a half-initialized handle. The dump tool relies on
  this to report a clean error.
- **NULL safety.** Every file function handles NULL without crashing.
  Cheaper to test once here than to chase a segfault in a later
  sub-phase.
- **Log levels filter.** Setting the level to ERROR and calling
  `plat_log(LOG_DEBUG, ...)` must not print. We do not capture stderr
  here; the test just verifies the call returns and does not crash.

### `test_ring`

Tests the sample ring, which is the storage behind every channel.

What it checks and why:

- **Bad arguments rejected at init.** NULL ring, NULL storage, cap 0
  all return -1 and leave the ring in a known-empty state. Anything
  that later calls `ring_init` can rely on a predictable failure mode.
- **Push under capacity preserves order.** Three pushes, read back
  0,1,2. If indexing is wrong when the ring is not yet full, every
  accumulation is suspect.
- **Push exactly to capacity.** Four pushes into cap 4, read back
  0,1,2,3. The boundary between "not full" and "full" is where
  off-by-one bugs live.
- **Wrap overwrites oldest.** Six pushes into cap 4, read back
  2,3,4,5. This is the invariant the whole design rests on: capacity
  is fixed, oldest data ages out, newest is always available.
- **Wrap twice.** Ten pushes into cap 3, read back 7,8,9. Ensures
  the modular arithmetic is right after more than one lap.
- **Clear.** After `ring_clear`, `count` is 0, `full` is false, and
  the ring accepts fresh pushes cleanly. Phase B's replay tool will
  reset rings between runs.
- **Capacity 1.** The degenerate case. Every push is both the first
  and the newest. Simple enough to be worth an explicit test.
- **`sample_as_f32` for every type.** Bool → 0/1, i32 → cast, u16 →
  cast, enum → cast. Every detector will read samples through this
  function, so its behavior for each type is a contract.
- **`sample_t` is 24 bytes with fixed field offsets.** A static
  assertion. The ingest storage math (`256 × 1024 × 24` ≈ 6 MB) is
  built into the type, and the A6 wire format will pack the same
  fields in a different order. If someone adds a field and the
  struct grows to 32 bytes, this test fails before the size change
  propagates into the storage array. It also pins the offset of each
  field, so a reordering is caught.

### `test_registry`

Tests the config loader, which turns `channels.toml` into the
descriptor table that everything else reads.

What it checks and why:

- **Empty file loads cleanly.** Zero channels, zero warnings, exit 0.
  A registry that fails on an empty input would break any pipeline
  that generates config dynamically.
- **Missing file is a hard error.** Returns -1. The dump tool exits
  with code 1. Distinguishing this from "empty file" matters because
  the operator needs to know whether their config was read.
- **Full channel with every field.** Writes a config with id, name,
  unit, type, role, min, max, controllable, is_regime and verifies
  every field is stored with the right value. This is the reference
  case: if this fails, nothing else can be trusted.
- **Multiple channels.** Two blocks load as two entries, lookups by
  id return the right one, lookup of an unknown id returns NULL.
- **Comments and blank lines.** Leading `#` comments and empty lines
  are skipped. The test also documents a real limitation: trailing
  comments on a value line are *not* stripped, because doing so
  requires knowing whether `#` is inside a quoted string. The channel
  still loads, just with the comment text in the value. This test
  pins that behavior so it is not accidentally relied on.
- **Unknown key warns and counts.** Adding a key the parser does not
  recognize bumps `warnings` by one and does not fail the load. The
  rest of the channel is kept.
- **Unknown type and role.** `type = "float64"` warns, and the type
  falls back to the default (f32). Same for an unrecognized role.
  Hand-edited configs with typos should load as much as possible.
- **Missing name drops the channel.** A `[[channel]]` with no `name`
  is unusable — it has no human identifier for logs or events — so
  it is removed and a warning is logged. The registry is compacted
  so `count` reflects only usable channels.
- **`registry_get_or_default` synthesizes.** Looking up an unknown
  id creates a placeholder with `role = ROLE_UNKNOWN`, `type = f32`,
  and a generated name. Calling it twice returns the same entry, not
  a second one. This is the path ingest uses for channels that
  arrive on the wire but are not in the config.
- **`registry_get_or_default` returns existing.** If the id is
  already loaded, the call returns the existing descriptor unchanged.
- **Capacity limit.** Loads `REGISTRY_MAX_CHANNELS + 5` channels and
  verifies `count` stops at the max, with at least one warning. The
  registry is bounded; a runaway config does not overrun the array.

### `test_ingest`

Tests the ingest engine, which is where packets become per-channel
history.

What it checks and why:

- **NULL arguments rejected.** `ingest_init(NULL, ...)` and
  `ingest_feed(NULL, ...)` return -1. Callers can rely on this rather
  than checking for NULL themselves.
- **Init without config.** `ingest_init(&ing, NULL)` succeeds with an
  empty registry. Useful for tests and for a future "auto-register
  everything on first sight" mode.
- **Single-channel round-trip.** One f32 sample in, `ingest_latest`
  returns the same value, timestamp inherited from the packet, and
  `CH_FLAG_VALID` set. The most basic path.
- **Three channels in one packet.** All three stored, all three
  retrievable. Confirms per-channel indexing.
- **Ring accumulates.** Ten samples, `ring_count` is 10, values in
  order. The ring integration with ingest works.
- **Ring wraps.** Feeds `INGEST_RING_CAP + 5` samples and confirms
  `ring_oldest` is sample 5 and `latest` is sample 1028. Ties ingest
  to the ring's wrap behavior end to end.
- **Unknown channel synthesized.** Feeding id 99 (not in config)
  bumps `unknown_channels`, grows the registry by one, and stores
  the sample. The synthesized descriptor has `role = ROLE_UNKNOWN`.
  This is the intended behavior for stray channels.
- **Unknown channel cached.** Two feeds of the same unknown id
  produce one registry entry, not two. `unknown_channels` counts
  feeds, not registrations, so it is 2 while the registry grew by 1.
- **Timestamp inheritance.** Sample with `timestamp_ns = 0` inherits
  the packet's. Sample with its own timestamp wins. Both directions
  checked because both are common (single-tick packets vs. batched
  samples).
- **Simulated flag propagates.** `PACKET_FLAG_SIMULATED` on the
  packet becomes `CH_FLAG_SIMULATED` on every sample. Phase D
  detectors will want to know which samples came from a simulation.
- **Stale flag preserved, valid not set.** A sample marked stale
  keeps `CH_FLAG_STALE` and does *not* get `CH_FLAG_VALID`. This
  invariant — exactly one of VALID or STALE — is what detectors
  rely on.
- **Out-of-range id dropped.** id ≥ 256 fails, `samples_dropped`
  bumps, no storage. The static array is bounded.
- **Oversized packet rejected before counting.** A packet with more
  than `PACKET_MAX_CH` channels returns -1 and does *not* bump
  `packets_seen`. "Seen" means "accepted", not "received", and that
  distinction has to be tested or it will drift.
- **Type/role fill-in from descriptor.** A packet with `type = 0` and
  `role = 0` gets them filled from the registry entry. This is how a
  minimal packet — just ids and values — can still arrive correctly
  typed.
- **Mixed known and unknown in one packet.** Both stored.
  `unknown_channels` counts 1 for the unknown one only.
- **`has_channel` false before any feed.** `ingest_latest` returns
  NULL, `ingest_state` returns non-NULL with `seen = false`. The
  asymmetry is deliberate: state exists for every in-range id, but
  the sample is only valid once a sample has arrived.
- **Accessors respect bounds.** id ≥ `REGISTRY_MAX_CHANNELS` returns
  NULL from `ingest_latest`, `ingest_state`, and `has_channel`.

### `test_packet_json`

Tests the JSONL encoder and decoder, which is the dev feed format.

What it checks and why:

- **Decode one f32.** The canonical shape: `{"t":...,"ch":[{"id":1,
  "role":1,"v":20.5}]}`. Value, id, and role all present.
- **Decode multiple channels.** A packet with three entries in
  different types. This is the test that caught the `find_key`
  scoping bug — with a `"type":"bool"` appearing in entry 3, entries
  1 and 2 must not pick it up.
- **Explicit type wins.** `{"type":"f32","v":20}` must store the
  value as f32 with the union holding the float bit pattern, not as
  i32 with the union holding the integer. This caught the
  type/union mismatch bug.
- **Shorthand `v` map.** `{"t":1,"v":{"1":20.5,"3":true}}` parses
  into two samples with inferred types. Used for hand-typed input.
- **Whitespace tolerance.** Spaces and tabs around keys, colons, and
  values are ignored. Hand-written test input is rarely compact.
- **Unknown keys ignored.** `"extra"` and `"note"` do not break the
  parse. Tolerant of `gensim` growing extra fields.
- **Key order irrelevant.** `"ch"` before `"t"` or `"src"` in a
  later position parses the same.
- **Negative numbers.** `-5.5` becomes `f32(-5.5)`. A common source
  of parser bugs if sign handling is wrong.
- **Empty string, missing `t`, missing channels, empty arrays.**
  All return -1. Failures are the correct default for malformed
  input.
- **Not JSON.** Random text returns -1.
- **Encode basics.** Output contains `"t":1000`, `"id":1`,
  `"v":20.5`. Locks the output shape so the decode tests have a
  counterpart.
- **Encode bool.** Value prints as `true`, type tag is `"bool"`,
  role is numeric. The encoder must round-trip what the decoder
  accepts.
- **Round-trip.** Encode a three-channel packet, decode it,
  compare every field. Catches asymmetric changes to either side.
- **NULL and zero-cap.** `packet_to_json(NULL, ...)` and
  `(..., NULL, 0)` both return -1. Defensive.
- **Returns needed length.** Passing a 4-byte buffer for a larger
  packet returns a value greater than 4 and does not crash. This is
  the "count even when truncated" contract, and it is tested
  explicitly because it was the second bug this sub-phase caught.

## Configuration

`configs/channels.toml` describes every channel Gardener knows about.
One `[[channel]]` block per signal:

    [[channel]]
    id           = 1
    name         = "coolant_temp"
    unit         = "C"
    type         = "f32"
    role         = "sensor"
    min          = 0
    max          = 150

Fields:

- `id` — required, 0..65535. The wire identifier.
- `name` — required, <= 31 chars. For humans and logs.
- `unit` — optional, <= 15 chars.
- `type` — one of `f32`, `i32`, `u16`, `bool`, `enum` (default `f32`).
- `role` — one of `sensor`, `setpoint`, `ctrl_out`, `actuator`, `status`,
  `counter`. Defaults to `unknown` and logs a warning.
- `min`, `max` — optional, sanity range for the range-check detector.
- `controllable` — `true` / `false` (default `false`). May Gardener write
  to this channel?
- `is_regime` — `true` / `false` (default `false`). Marks the channel as
  a regime selector for baseline segmentation.

The parser handles a small TOML subset: `[[table]]` headers and
`key = value` lines with quoted strings, numbers, and booleans.
Trailing comments on a value line are *not* stripped — put comments on
their own line. Nested tables and arrays are not supported.

## Design notes

- `sample_t` is natural-aligned in memory (24 bytes) and will be packed
  to 18 bytes on the wire in A6. The 24-byte size and field offsets are
  asserted by a test so the ingest storage math can't silently change.
- `ROLE_UNKNOWN = 0`. Zero-initialized descriptors mean "unknown", not
  "sensor". Unknown channels get logged and are easy to spot.
- `plat_log` writes to `stderr` only. `stdout` is reserved for
  machine-readable output (dump tool, JSONL stream).
- No OS headers outside `src/platform/`. This keeps the eventual MCU
  port (V2) a folder swap rather than a rewrite.
- Registry string storage lives in a fixed arena inside the registry
  struct. No heap; the registry is trivially copyable and embeddable in
  a larger static struct (as A3's ingest does).
- Registry loads are append-only. Calling `registry_load_toml` twice on
  the same registry doubles its entries. Add a `registry_clear` when
  runtime reload is needed.
- A `[[channel]]` with no `name` is dropped with a warning. One with no
  `role` is kept with `ROLE_UNKNOWN` and a warning.
- `REGISTRY_MAX_CHANNELS` is 256, and the string arena is 64 bytes per
  channel. Both are compile-time constants; bump them if a system needs
  more or longer-named channels.
- `ingest_t` is static: `REGISTRY_MAX_CHANNELS` × `INGEST_RING_CAP`
  samples, ~6.3 MB total with the embedded registry. No heap, no
  allocation after init. Fits on an MCU with external RAM or a modest
  SBC.
- `INGEST_RING_CAP` is 1024 samples per channel — ~102 s of history at
  10 Hz. Enough for the baseline and rate-of-change detectors in Phase
  C; resize when their windows become concrete.
- `PACKET_MAX_CH` is 64, smaller than `REGISTRY_MAX_CHANNELS` on
  purpose. A single tick carries one source's worth of channels, not the
  whole registry. Keeps `packet_t` around 1.5 KB so it can live on the
  stack.
- Unknown channel ids are synthesized into the registry on first sight
  and cached. Samples are stored normally; the descriptor has
  `role = ROLE_UNKNOWN` so downstream detectors can see they're
  unclassified.
- A packet with more than `PACKET_MAX_CH` channels is rejected before
  any counter is bumped. `packets_seen` counts *accepted* packets, not
  received ones.
- Every sample in a ring has exactly one of `CH_FLAG_VALID` or
  `CH_FLAG_STALE` set. Detectors can rely on that.
- Timestamps: a sample's own `timestamp_ns` wins; if zero, the packet's
  timestamp is inherited.
- `PACKET_FLAG_SIMULATED` propagates to `CH_FLAG_SIMULATED` on every
  sample. Detectors can down-weight simulated input in a mixed
  environment.
- `packet_from_json` honors an explicit `"type"` for both the type tag
  and the union bytes. Inferred types (when `"type"` is absent) pick
  i32 for whole numbers and f32 otherwise.
- `packet_to_json` returns the length the full encoding needs, even if
  the caller's buffer was too small. Callers detect truncation by
  comparing the return value to `cap`.
- `find_key` in `packet.c` stops at the end of the current object. This
  keeps a key like `"type"` in a later entry of the same packet from
  being matched while parsing an earlier entry.
